Theoretical Part · 2026

Coevolution of Neural Network Agents in a 3D Arena Without Gradients

This document is the knowledge base for defending the TopGun Research project. It collects definitions, rationale for method selection, environment description, and ready-made answers to typical committee questions. The language is deliberately plain: no unnecessary academic fluff, but with precise facts from the project implementation.

Topic Relevance

Why teach agents to fight in a simulator at all?

Artificial intelligence in games and robotics often runs into one problem: the environment does not provide a ready-made "error gradient". A physics simulator is a chain of if-statements, collisions, and discrete events (hit / miss, kill / no kill). You cannot simply run backpropagation through such an environment the way you do when training on images.

Classical reinforcement learning (RL) works well when rewards are frequent and the environment is "soft." In combat scenarios, rewards are rare (a kill — once per match), and the opponent also changes — the problem landscape keeps shifting.

Evolution Strategies (ES) offer an alternative: instead of a gradient, we evaluate entire sets of neural network weights with a single number — fitness. This is easier to explain, easier to reproduce, and convenient to parallelize across multiple CPU cores.

Practical meaning: the project shows how, without heavy ML frameworks and a GPU, you can obtain meaningful agent behavior in a nontrivial 3D environment — with partial visibility, different weapons, and a procedural map.

Goal and Objectives

What exactly we are researching and what should come out of it.

Goal

Develop a research stand in which two neural network agents coevolve in a procedural 3D arena using evolution strategies, and demonstrate that the method yields steady behavioral improvement without a differentiable environment.

Objectives

  1. Model a deterministic game environment: map, weapons, partial visibility, 60 FPS physics.
  2. Describe the observation vector (28 features) and discrete agent actions (5 network outputs).
  3. Implement a population algorithm: elite, crossover, Gaussian mutation, two independent populations.
  4. Design a fitness function balancing victory, exploration, and anti-passivity.
  5. Ensure reproducibility: fixed seeds for comparison, random seeds during training, CSV/JSON export.
  6. Visualize the process: live matches, generation charts, checkpoint comparison, network weight analysis.

Problem Statement

What the agent sees, what it does, and how the result is evaluated.

Two agents — blue and red — spawn on a procedural 12×12 cell map (each cell is 4 m). The map has walls, three weapon types (pistol, bow, katana), and limited field of view.

Observations (28 numbers)

Each frame the agent receives a normalized vector:

  • Own state: X/Z position, look direction (sin/cos), HP, weapon type, reload cooldown.
  • Opponent (if visible in a 72° cone with no wall between): visibility flag, distance, angle, enemy HP and weapon.
  • Nearest weapon (if visible): type, distance, angle.
  • Look ray: distance to obstacle and target type (wall / weapon / enemy).
  • 8 rays in a circle (every 45°): distance to wall — to "sense" the surroundings.

Actions (5 network outputs)

The neural network outputs 5 numbers from 0 to 1 (sigmoid). If a value > 0.35 — the action is active: forward, left, right, shoot/strike. Backward is disabled in the current version — to avoid rewarding retreating into a corner.

Match conditions

  • Duration: up to 20 seconds or until the first kill.
  • Player HP: 3. Weapon damage: 1 per hit (katana — melee arc attack).
  • Partial observability: enemy and weapons are not visible behind walls or outside the field of view.
  • Determinism: with the same map seed and weights, the match result repeats.
Key environment constraint: fitness is the sum of rewards and penalties for the entire episode. There is no differentiable loss function inside the simulation. That is why a method without backprop through the environment was chosen.

Evolution Strategies — Theory in Plain Language

How the network learns when you cannot take a derivative.

Imagine that neural network weights are a genome. We have a population of 48 such genomes per side (blue and red separately). Each generation:

1. Evaluation — 48 matches against the enemy champion → 2. Sort by fitness → 3. Top 8 into elite → 4. Crossover + mutation → new generation

Main operators

  • Mutation: random noise is added to weights from a normal distribution. Noise strength σ = 0.12, multiplied by 0.995 each generation (gradual "cooling"). Minimum σ = 0.03.
  • Crossover: for each child weight, a value is randomly taken from one of two elite parents (uniform crossover).
  • Elitism: the best 8 individuals pass unchanged — progress is not lost due to an unlucky mutation.
  • Champion: the best genome of the generation. It plays live matches and appears in UI statistics.

Unlike genetic algorithms on bit strings, here the genome is a continuous vector of MLP weights. This is the standard Neuroevolution approach.

Coevolution

Why the "teacher" keeps changing.

Blue and red populations evolve independently, but each evaluation match is a fight against the current champion of the opposite side. If blue finds a successful tactic, red's fitness drops — and vice versa.

Such a landscape is called non-stationary: what was good in generation 50 may become weak in generation 80, because the opponent has also improved. This resembles an arms race in nature (the "Red Queen" effect).

How the project handles this

  • Adaptive mutation: if one side wins >60% of matches after 80 decisive fights, the losing side temporarily gets a higher σ (up to 1.5×, maximum 0.22) — faster search for a counter-strategy.
  • Random map during training: agents cannot "memorize" one wall layout.
  • Shaping rewards: small bonuses for movement, exploration, and picking up weapons help avoid getting stuck in the local optimum of "stand and wait."

Why ES, Not Reinforcement Learning (PPO, etc.)

Comparing approaches — not "what's trendier," but what fits the environment.

Criterion Policy Gradient / PPO Evolution Strategies (our choice)
Gradient through environment needed? Yes, or a complex surrogate No — only a fitness number at the end of the match
Sparse reward (kill once per episode) Requires careful reward shaping and a value baseline Population "averages out" noise; elite preserves successful mutations
Parallelism Depends on on-policy sampling Up to ~96 independent matches on worker threads
Interpretability Gradients in hidden layers Direct A/B weight comparison between generations
Network size Millions of parameters (deep RL) ~2,500 parameters — ES is effective on small MLPs
Project dependencies PyTorch / TF, often GPU Pure JavaScript, CPU, no external ML libraries
Important for defense: we do not claim that ES is "better than RL in general." We show that for this non-differentiable environment with a small MLP and coevolution, ES is a deliberate and workable choice.

Why is the network small?

ES scales poorly to millions of parameters: each individual requires a full match run. 28 inputs describe the situation explicitly (position, enemy, walls); a deep convolutional network is not needed. A small MLP is evaluated faster and is easier to analyze in the "Neural Network" panel.

Fitness Function

How a single number reflects behavioral quality over a match.

Each agent's fitness is the sum of rewards and penalties for the episode. The main signal is victory or defeat, but without small bonuses agents often get "stuck" in draws.

Event Value Comment
Victory (kill) +12 + speed bonus Bonus: (20 − tkill) × 2 — faster victory is more valuable
Defeat −12 HP dropped to 0
Draw (timeout) −5 … −13 Penalty grows after the 8th second to discourage "camping" in a corner
Weapon pickup +3 Once per match
Damage to enemy +2.5 per 1 HP Intermediate signal before a kill
New map cell +0.08 Exploration; ×2 in the first 10 generations
Saw a weapon +0.5 At least once per match
Movement +0.012 / unit of distance Cap +1.2 per match
Stuck on wall / corner / idle per-frame penalties Anti-passivity
About reward shaping: small bonuses are not a "hint from the developer," but a standard technique when the main reward is too sparse. Without them, ES takes a long time to find meaningful behavior. The main success criterion is rising win rate and shorter time to kill among champions.

Methodological Protocol

What distinguishes research from "run it and hope."

A. Random map seed during training

Each eval match uses a new wall layout. The agent learns to generalize navigation, not memorize one maze.

B. Fixed seed during comparison

A/B checkpoint testing uses WORLD_SEED = 42 — the same environment for both contenders.

C. Separation of eval and champion stats

Population evaluation matches do not count toward the main win rate. UI statistics — only matches of the best genomes.

D. Turn alternation

On even frames blue acts first, on odd frames — red. Reduces bias from "who shot first."

E. Adaptive mutation

When one side dominates (>60% wins), the losing side gets a higher σ.

F. Protocol export

CSV of generation history and JSON with algorithm, architecture, and fitness model.

What to include in the report

  • history.csv — fitness and win-rate dynamics across generations.
  • protocol.json — full experiment description.
  • Screenshots/replays of best matches and checkpoint comparison (gen-50 vs gen-200).
  • Checkpoints every 25 generations (data/checkpoints/gen-*.json).

Expected Results

What to look at to show that the project works.

  • Rising average fitness of champions across generations (chart on the research stand).
  • Lower draw rate — agents stop "being afraid" to fight.
  • Emergence of tactics: weapon search, wall flanking, pursuit of a visible enemy.
  • Faster kills — average time to first kill drops (bestKillTimeMs).
  • Alternating dominance of blue and red — a sign of living coevolution, not stagnation.
  • A/B checkpoints: a later generation consistently beats an earlier one on a fixed map.
How to phrase the conclusion: "A reproducible neuroagent coevolution stand was developed. The ES method without gradient through the environment provides measurable behavioral progress in a procedural 3D arena with partial observability."

Limitations and Future Development

Honestly naming weak points is a plus at defense, not a minus.

  • Network size: ~2.5K parameters — a ceiling on behavioral complexity. Do not expect "human-level" play.
  • Sample efficiency: ES requires many matches. For production this is more expensive than PPO on GPU.
  • Shaping dependence: reward balance affects play style. Different weights — different tactics.
  • Coevolutionary cycles: "swings" are possible — one side dominates, then the other.
  • 2D navigation: movement on the XZ plane, no jumping or verticality.
  • One opponent type: mirror agent with the same architecture.

Possible improvements

  • Hybrid ES + fine-tuning (e.g., training a critic on replays).
  • More map and mode variety (team combat, multiple weapons at once).
  • Comparative benchmark with PPO on the same environment (as a separate study).
  • Memory maps / recurrent networks for long-term planning.

Arguments and Counterarguments for Defense

Typical committee questions and ready-made answers. First — a possible objection, then — your response.

"Why didn't you use deeper neural networks / RL like in modern games?"
Counterargument Deep RL (AlphaStar, OpenAI Five) is the industry standard; ES is outdated.
Response Deep RL requires enormous resources and a differentiable or emulated environment. Our goal is a research stand with transparent logic, not SOTA in Dota 2. The environment in pure JS is non-differentiable, the network is small (~2.5K parameters), ES parallelizes on CPU and yields measurable progress. This is a deliberate trade-off: reproducibility and clarity matter more than scale.
"It's just a game. What's the scientific value?"
Counterargument A game simulator has no relation to real-world tasks.
Response Combat simulators are a standard benchmark in multi-agent AI (see ViZDoom, Pommerman, Google Research Football). Our environment models real difficulties: partial observability, sparse reward, non-differentiable physics, adaptive opponent. The value lies in the training methodology, which can be transferred to robotics, drones, and autonomous systems in unknown environments.
"Isn't reward shaping cheating? You're telling the agent what to do."
Counterargument Artificial bonuses distort the "true" goal — victory.
Response With sparse reward (a kill once every 20 seconds), ES barely learns without shaping — this is a known sparse reward problem. Shaping bonuses for exploration and weapons are a bridge to the main reward. We document all coefficients in FITNESS_MODEL and export them to JSON. The final metric for the report is champion win rate and kill time, not the sum of small bonuses.
"How do you prove the result isn't random chance?"
Counterargument One lucky match is not proof of learning.
Response Three levels of evidence: (1) dynamics over hundreds of generations in CSV; (2) A/B checkpoint comparison on a fixed seed — gen-200 beats gen-25; (3) simulation determinism — replaying a match with the same weights gives the same result. Plus unit tests for physics and the network.
"Why do two populations evolve separately, not one shared population?"
Counterargument Mirror coevolution (one population, paired opponents) is more natural.
Response We use an "evaluation against champion" scheme — a classic coevolutionary archive approach. It is more stable: each genome is evaluated against one strong opponent, not a random weakling from the population. Both sides are symmetric in architecture and hyperparameters — a fair comparison.
"Isn't ES very slow — millions of episodes?"
Counterargument Sample efficiency of ES is worse than PPO.
Response Yes, ES is not sample-efficient — we acknowledge this in the limitations. But a match lasts at most 20 seconds of simulation, the network is tiny, evaluation runs in parallel on worker threads (up to ~96 matches simultaneously). For academic research on CPU this is enough: hundreds of generations overnight. Parallelism is a strong side of ES.
"Why a random map during training if comparison uses a fixed one?"
Counterargument Contradiction: sometimes random, sometimes fixed.
Response These are two different modes with different goals. During training, a random seed forces generalization of navigation. During generation comparison, a fixed seed removes the influence of a lucky wall layout — a clean test of "who plays better." This is standard in ML: train on distribution, evaluate on fixed benchmark.
"The agent only sees 28 numbers — is that enough?"
Counterargument No pixels from the screen — so no "real vision."
Response This is structured state — a deliberate simplification for an academic project. Analogous to lidar + game state in robotics. 28 features include position, enemy, weapons, and 8 rays to walls — enough for the tactic "find weapon → track down → attack." Pixel input would require a CNN and an order of magnitude more computation.
"What if agents only learn to draw?"
Counterargument A passive strategy is a local optimum.
Response That is exactly why fitness includes: a growing timeout penalty after 8 seconds, penalties for idleness, corner camping, and wall grinding; bonuses for movement and exploration. In early generations exploration is ×2. The chart shows falling draw rate — a direct answer to the experiment.
"Can the experiment be repeated on another computer?"
Counterargument Without Docker and the cloud, reproducibility is questionable.
Response The project runs on Node.js without GPU: npm install && npm run dev. All hyperparameters are in shared/config.js, the protocol exports to JSON. Simulation is deterministic by seed. Checkpoints every 25 generations can be shared separately. In the report — Node version, protocol screenshot, CSV history.

Glossary

Short definitions of terms that may come up.

Agent
Game character controlled by a neural network. In the project — blue or red.
Evolution Strategies (ES)
Method for optimizing neural network weights through population, selection, and mutation without gradient through the environment.
Fitness
A single number — how well a genome played a match. Higher is better.
Genome
All weights and biases of the neural network that define agent behavior.
Coevolution
Simultaneous evolution of two populations, where opponent strength also grows.
MLP
Multilayer perceptron — a simple fully connected neural network.
Champion
Best genome of the current generation. The enemy population is evaluated against it.
Reward shaping
Additional small rewards that help learning when the main reward is sparse.
Seed
Number that determines the map layout. Same seed — same map.
Partial observability
The agent does not see the whole map — only a 72° cone and what is not blocked by walls.
Determinism
With the same inputs (weights + seed), the simulation gives the same result.
Elitism
Best individuals pass to the next generation unchanged.
